# Maintained-owner opportunity audit

Scope: which imported operations improve a current Demuxe playback path without silently changing requested output? This is a source review, except where linked browser/host executions provide stronger evidence. Exact sources are in `owner-audit-assets.json`; imported definitions and controls remain in the preceding campaign.

- `native/remux/remux.c` owns full-packet demux/mux, selected streams, AAC configuration, timestamps, header restoration and copied codec metadata. The current source does not contain the proposed AAC normalization. The isolated candidate fixes the two qualified AAC declarations without rewriting packets. FFmpeg already interprets the absolute-address, missing-tfdt and stripped/laced inputs exercised here. A second generic box/lacing repair layer is not warranted by those passing cases.
- `web/native-remux-player.js` owns generation checks, workers, retained random-access points, MSE append/removal and seek replacement. Its real `pump()` removes through `cut - .00001`. The actual SourceBuffer regression retains [4,6]; the +0.0001 control removes everything. This is executed browser evidence, not merely the preexisting unit test.
- `web/native-remux-source-worker.js` publishes a completed read only while not stopped; `web/native-remux-player.js` checks worker generations. Neither is the imported simulated DecompressionStream publication sink. D05/D12's aggregate decompression, cancellation and native-allocation work remains a distinct hardening follow-up, not a newly proven memory limit.
- `src/internal/native-player.ts` already has selected audio-track ownership and transactional remux replacement. D65 actually exposes/selects the two authored Ogg FLAC tracks, but the maintained remux route subsequently fails with missing selected packet PTS. The finite page projector is therefore a demonstrated compatibility opportunity. Its explicit serial and whole-source digest bind selection to a source; original page bytes and full PCM remain exact. It is not a generic Ogg validator or a new automatic track-selection policy.
- `src/internal/playback-plans.ts` defines finite playback owners. Native consumes media elements/MSE; Hybrid and Software consume mpv audio. Native audio filters are rejected, and the qualified Hybrid filter is scalar volume. There is no native decoded-buffer edit/FIR/IIR/periodic-loop scheduler to which D35/D55/D61 can simply be attached. Those are promising bounded audio-preview features, but new scheduler/API/lifecycle work is deferred; the existing component positives do not establish live playback.
- `src/preview/controller.ts` and `src/preview/providers.ts` expose `getFrame` and encoded image results, with cancellation/cache bounds and existing authored/browser preview providers. They do not expose TIFF page selection, sample-indexed audio edits, effect rendering or audio output buffers. New image-page and audio-preview operations need a consumer contract and a cheapest-correct maintained baseline before full-cost work. Existing image-preview studies and their stopped exact-alpha/color profiles remain intact.
- D42's chained Opus and D57's sparse WAVE fail the forced maintained remux screen. Under default routing, chained Opus starts through native-direct, but reports 2.235083 seconds rather than the independent concatenated-link reference's 3.2294375 seconds; basic playback is not a global-chain timeline pass. The dense WAVE reference plays through the default route while sparse WAVE still fails. They would require an additional per-link or held-span native scheduling owner, explicit memory budgets, seek/cancel and clock qualification. No current graph implementation was silently invented to turn the imported offline scheduling proof into a player pass. Their maintained-owner preparation/correctness/performance remains pending.
- D60 is a narrowly source-bound repair: the original packet descriptors are authoritative only for these authored sources. Re-executed parsing rejects all 76 dependent samples as IDRs; repaired bytes equal the original and ten maintained-player seek pictures match. The damaged input's seek fails. This supports a restricted repair investigation, not relabeling arbitrary decoded pictures or trusting caller-provided hashes as authentication.
- D72's initial duration-loss hypothesis was not a confirmed cause. The actual negotiated output is MP4, so changing the WebM muxer cannot affect this route; that failed experiment is retained. All six held-frame seek pictures can match the direct reference and the final held interval [1.625,2.75] exists. Consecutive seeks followed by play in the terminal held picture still time out in the maintained output/seek evidence path. The full lifecycle gate therefore fails. Packet `duration_time` omitted by host ffprobe is not proof that the MP4 has lost its presentation interval. Reopen on this specific Native seek/output-evidence boundary; do not adopt the irrelevant muxer patch.
- D73 preserves the coherent anamorphic and rotated geometry in both maintained routes. Actual dimensions are 320x96 and 96x320. These checks do not overturn R008's prior Hybrid/Software pixel-fidelity stop or resolve contradictory real-source metadata authority.

Existing positive owner studies are not discarded merely because a new external subgroup remains unqualified. Likewise, imported negative contracts (exact edit-list audio, fractional-rate loop exactness, metadata cropping, cold recovery and strict MP3 windows) are not weakened to make stage counts look complete.
