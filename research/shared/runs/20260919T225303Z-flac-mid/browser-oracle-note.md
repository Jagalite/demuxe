Initial browser oracle incorrectly assumed signed16 normalization always divides by32768. Chrome here scales positive samples by32767 and negative samples by32768 (see captured examples), so float arithmetic on decoded channels is not the specified integer mono oracle. Final reference independently decodes original stereo to signed16, computes floor integer average, encodes normal FFmpeg FLAC, then compares both through the same native consumer. The initial mismatches and executed harness remain preserved.
