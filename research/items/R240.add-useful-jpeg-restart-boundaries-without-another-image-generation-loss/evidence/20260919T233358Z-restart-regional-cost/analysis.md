# Add useful JPEG restart boundaries without another image-generation loss

Actual jpegtran entropy reserialization adds a restart boundary every MCU row to a 512×512 grayscale JPEG while preserving all 262144 quantized coefficients and quantization tables. A validated row-interval adapter then creates four 512×64 regional JPEGs by reusing their compressed entropy segments and changing height/restart numbering. Independent host regional pixels equal full-source crops exactly; browser complete RGBA output is exact for all 16 requested regions. Missing and mismatched restart geometry reject; a stale decoded bitmap closes, and all 171 ImageBitmaps close. The correct cheap baseline decodes once and retains the whole image for all requests. Nine alternating whole tasks charge candidate restart authoring, binary input transfer, parsing, regional construction, every decode/draw/readback/hash and teardown: baseline 17.893 ms, candidate 130.348 ms, saving -628.47% with bootstrap95 [-991.37, -376.97], failing the declared 10% lower-bound gate. Original/restart file sizes are 147894/148061 bytes. Correctness passes but this repeated regional workload does not repay authoring and repeated small decodes against a retained full-image baseline. Both paths read the full compressed source; no sparse network, browser parallelism or physical memory claim. Stop this measured variant, preserving the useful coefficient-preserving authoring capability.

Next: Reopen with a justified retained-memory constraint, a real regional source adapter, or a different decoder scheduling workload that repays authoring and extra metadata. Do not replace the one-decode retained baseline with repeated full decodes to manufacture a benefit.
