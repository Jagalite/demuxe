# Reproducing the unified-engine experiment

Run from the repository root. The default active run is sealed: every maintained generator refuses to modify it. Create a NEW direct child of this item's evidence directory and set `UNIFIED_RUN=research/items/unified-hybrid-software-engine/evidence/<new-run>` for new experiments. Keep active-run.txt pointing at the reviewed study until the new run has its own decision. `python3 research/items/unified-hybrid-software-engine/tests/validate.py` verifies the captured study without writing files or requiring unchanged production binaries.

The baseline runtime and original link command come from granular-engine-loading screen-01; full-study-02 supplies matched full Hybrid/Software binaries and independent fixture references. These are pinned by the input references and manifests. The engine build uses the existing detached engine-build-01 checkout and Emscripten 4.0.14. No dependency downloads, FFmpeg rebuild, codec registry changes or dynamic linking are needed.

1. Create the run directory, PLAN.md, snapshots/, runtime/ copied from screen-01/snapshots/runtime, fixtures/ copied from full-study-02, and variants/{baseline,software-baseline} copied from full-study-02. Keep the user MKV outside the repository.
2. Run `python3 research/items/unified-hybrid-software-engine/tests/build.py`.
3. Run `python3 research/items/unified-hybrid-software-engine/tests/prepare-runtime.py`. This patches only the new runtime snapshot. It preserves the maintained browser harness, including its rotation, foreground and sealed-run guards. Historical tooling under evidence is an immutable provenance snapshot; use the maintained tests directory for new execution.
4. Run browser.mjs with VARIANT=baseline or unified, BROWSER=chrome or firefox, FIXTURE=h264 or user, EXPECT=hybrid or software. Set FORCE=software for explicit Software; automatic Hybrid trials must leave FORCE unset to test recovery. Example: `VARIANT=unified BROWSER=chrome FIXTURE=user EXPECT=hybrid node research/items/unified-hybrid-software-engine/tests/browser.mjs`.
5. Generate rotation fixtures with recorded rotation90-fixture.json commands, verifying its display matrix. Do not use the initial rotate metadata command: it produced no display matrix in this host FFmpeg version. Use the recorded oracle commands.
6. Run correctness, rotation and analyze-pictures.py before performance. Mutating commands require UNIFIED_RUN; never edit the historical snapshots to change their behavior. Pictures are compared with host FFmpeg output, inverted adverse control and matched baseline. Historical setup/foreground failures remain failures; per-profile gates require successful corrected trials.
7. Run run-performance.py and analyze-performance.py. Browsers run sequentially and visibly with foreground PID checks. Wasm only is gzip-paced through one aggregate 10 Mbps response budget with 80 ms initial delay; media, JS and fonts are local. Do not run other browser tests/builds concurrently. The user media path is fixed in browser.mjs.

The integration.patch is a review artifact against the frozen runtime. It edits generated JS only inside this lab snapshot; production integration must port the changes to maintained TypeScript and rebuild generated output. Both modes retain separate workers/heaps and their existing presenters. The cache is per Player, not global across tabs or players. Cache/preparation alias reporting and failure/retry policies need production treatment. The experiment does not qualify experimental-yuv, all formats, remote streaming, HDR, endurance, or release packaging.
