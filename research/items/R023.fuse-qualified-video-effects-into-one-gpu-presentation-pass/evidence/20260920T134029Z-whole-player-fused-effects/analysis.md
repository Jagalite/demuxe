# R023 within-Hybrid whole-player qualification

The isolated fused WebGPU presenter is correct for the declared native-size SDR profile, but it does not beat the cheapest tested actual-player alternative. Five completed paired trials show **8.52% higher median steady Chrome CPU**, with GPU lower in only one pair. The required10% median reduction and every-pair improvement gate fails. This is a measured cost result, not a missing runtime or a fidelity failure.

Both arms run the actual Player with the same browser WebCodecs video, mpv demux/PCM audio, and mpv/libass subtitle owners. The baseline uses native Canvas2D `invert(1)`, maintained90degree retained-frame geometry, and cached subtitle tiles. It does not perform a CPU readback or artificial CPU pixel loop during timing. The candidate imports actual decoded VideoFrames into WebGPU, rotates/inverts in one pass, and composites a cached premultiplied subtitle texture. Both use the same narrowly admitted explicit display-effect request. Neither changes production admission. Tier effect: **Hybrid to Hybrid**, not a Software-to-Hybrid upgrade.

The fixture is320x180 H264 with AAC and embedded ASS, explicitly tagged BT709, displayed at native180x320. Compressed video, audio and subtitle stream hashes match between input containers; equal-size containers differ only in generated container identity. At PTS1/6/10, the Canvas baseline differs by at most1 RGB level from an independent integer rotation/inversion/straight-alpha oracle using the same actual decoded frame RGB and actual subtitle bitmap raster. GPU differs by0/1/0; direct paired output differences are at most1. The declared gate was3 RGB levels with opaque alpha. Every tested picture exercises2214 nonzero subtitle-alpha pixels,186 partial-alpha pixels, and differing wrong-identity/wrong-alpha controls. This proves the display operations, not independent decoder color fidelity: R008's separate FFmpeg-versus-Hybrid chroma-edge issue remains outside this within-Hybrid comparison.

Both arms execute moving pictures and measured440/880Hz stereo markers. Forward/backward seeks, same-file source replacement from PTS10 to PTS1 with a new source identity, EOF, immediate open cancellation, and final destruction pass. Replacement pictures match the original PTS1 outputs exactly. All surfaces and workers close. Exact unsupported filter/mode combinations reject. Source-content diversity, scaling, HDR, arbitrary filters and production integration remain outside this profile.

Performance uses five alternating pairs, five seconds warmup and20 seconds steady playback per trial. All relevant Chrome process CPU is sampled; process sets remain stable in every steady sample. Actual frame delivery exceeds the predeclared29fps gate, selected-frame missing counters remainzero, and every measured browser process exits between trials. Correctness oracles, readback and audio analysers are disabled during performance. Device/pipeline construction is included in startup, and seeks/EOF/player teardown are recorded. Browser launch, server CPU and physical energy are excluded. Background user workloads were not stopped; summed RSS is a proxy that may double-count shared pages.

A secondary startup CPU observer initially assumed a stable process set. A normal process departure caused that observer to abort the first pair4 GPU attempt before warmup/steady measurement. The failed attempt and original script are retained. Only startup CPU accounting was changed to retained cumulative process observations; the runtime, stable steady primary, ordering and gates were unchanged. Pairs4/5 then completed. Exactly five complete pairs form the final comparison; no primary measurement was discarded. Full lifecycle CPU is explicitly observed sampled CPU, because departed-process exit tails may be missed. The partial resumed file's benefit flag is not the final gate; `combined-performance.json` is authoritative.

Paired GPU CPU changes are+18.64%,+5.17%,+8.52%,+12.32%,-3.60%. Median startup wall change is+0.91%; median observed lifecycle CPU change is+4.46%. Median peak summed RSS changes-6.12%, with wide sign changes across pairs, and is not an attributable allocation saving. These secondary observations do not override the failed primary gate.

Disposition: stop this whole-player fused presenter profile. Retain the earlier prepared-RGBA component result as historical evidence against its different CPU-loop baseline, not as whole-player savings. Reopen only for a new representative workload/effect set with a predeclared benefit threshold and the cheapest correct native Canvas alternative. No production source or routing changed.
