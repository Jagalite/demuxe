# Integrated streaming development stage

The current implementation connects the shared native coordinator to mpv in the
isolated integration profile. It is still unqualified for release. The sections
below preserve the earlier prototype's scope; they do not describe the current
implementation as native-only. See `docs/STREAMING-MODERNIZATION-STATUS.md` for
artifact-specific results and open milestones.

The first Chrome Hybrid/HLS run passes three presented resolution changes with
one mpv lifetime, followed by paused selection and seeking. The four-case
candidate-10 matrix still fails DASH startup and Software switching. Candidate 11
adds demux-owned DASH IDs and a measured worker-pool capacity correction. ABR,
standard live/DVR, period replacement and the public quality API remain open.

## Historical synchronous prototype

The original native packet-transition model is **not connected to mpv or any shipped
runtime**. It exercises one proposed boundary from the architecture decision;
passing its native tests does not qualify manual switching or ABR.

The demux owner provides already-validated, same-family closed-GOP representations.
The model waits for matching random-access points on old and candidate streams,
keeps old packets during preparation, and bounds retained candidate/old packets.
It has no playback clock, network scheduler or decoder API. Frame/codec eligibility,
mpv segmented-packet integration, paused-switch refresh, error-role handling and
actual A/V/cue qualification remain required.

Reproduce ownership and real packet/decode characterization separately:

```sh
python3 experiments/streaming-modernization/integration/test-native-transition.py \
  --native /absolute/pinned-native-build --output /absolute/new/unit-evidence
python3 experiments/streaming-modernization/integration/probe-packet-transition.py \
  --native /absolute/pinned-native-build --fixtures /absolute/fixtures \
  --output /absolute/new/packet-evidence
```

The packet probe uses fixture-only representation grouping, one AVFormatContext,
an unchanged audio decoder, and new video codec contexts only at accepted closed-GOP
boundaries. It decodes without a playback clock. Add `--fixed` for the equivalent
control workload. Preparation accounting excludes the current caller-owned packet
and decoder allocations; it is not an aggregate player memory bound.

`files/patches/ffmpeg/0011-dash-continuous-fmp4.patch` began as a native-only
experiment. With `--continuous-fmp4`, it keeps MOV open across VOD fragments that
share an ftyp initialization. Baseline DASH loses an AAC frame per segment in the
controlled fixture; fixed-quality playback has the same loss, while decoding the
concatenated original fragments does not. This option defaults off; the later
experimental mpv integration enables it for its qualified finite fMP4 inputs.
It is not a live implementation or a public quality option.

Build that isolated FFmpeg experiment from the pinned archive:

```sh
python3 experiments/streaming-modernization/build-native-probe.py \
  --archive /absolute/verified-cache/ffmpeg.tar.gz \
  --patch experiments/streaming-modernization/transport/files/patches/ffmpeg/0010-strict-stream-resource-errors.patch \
  --patch experiments/streaming-modernization/integration/files/patches/ffmpeg/0011-dash-continuous-fmp4.patch \
  --output /absolute/new/native-build
```

The latest native probe passes video/audio timestamp continuity with
`--continuous-fmp4`. Adding `--candidate-delay 3` shows why this is still insufficient:
one synchronous parent read blocks for roughly three seconds. That result does not
mean continuous clocked playback passed. Nonblocking preparation and mpv integration
remain open; the prototype must not be used as the player's quality implementation.

## Independent preparation and mpv stage

The later shared coordinator replaces the blocking prototype for the next stage.
FFmpeg alone produces copied segment plans. Child tasks perform incremental
container reads, and the demux-owned session accepts matching keyframe boundaries.
The opt-in mpv patch is generated by `make-mpv-patch.py`; it is not qualified or
promoted to the release path. Existing compatibility adapters remain available.

Reproduce the shared native session test (actual decode, paced output, no mpv):

```sh
python3 experiments/streaming-modernization/integration/probe-async-transition.py \
  --native build/streaming-modernization/native-plans-04 \
  --fixtures build/streaming-modernization/fixtures-02 \
  --output /absolute/new/session-evidence --session --candidate-delay 3
```

`native-session-02` passes HLS and DASH with continuous decoded timestamps and
three resolution switches. `native-session-01` preserves the initial unselected
packet failure. Browser/mpv switching, ABR and live milestones remain open.
