# Selected codec adapter evaluation

Date: 2026-10-29. Scope: source-contract comparison against the pinned MediaBunny 1.63.0 audit and the existing individually downloadable Demuxe audio providers. This is not new codec execution or replacement qualification.

Retain the current codec slices. The implemented MediaBunny inspection, preview and packet-copy adapters do not need an additional fallback codec download. Adding the audited AC-3/DTS extensions would add another FFmpeg-based implementation, not remove FFmpeg. No measured transfer, startup, fidelity or maintenance improvement currently establishes a reason to replace those slices. ProRes is a distinct candidate for later software preview decoding; it is not needed for the currently qualified VP8/AVC profiles.

The API direction matters. Demuxe's existing [packet decoder](../packages/provider-audio/src/packet-decoder.ts) consumes packets synchronously, returns owned `AudioFrame` arrays and exposes `reset/dispose`. MediaBunny's [custom-coder interface](https://github.com/Vanilagy/mediabunny/blob/0f80f47e617b576737ffd4ce39a626eb7c7e934e/src/custom-coder.ts) publishes samples through a callback and allows asynchronous initialization/decode/flush/close. Wrapping an existing synchronous Demuxe owner for selected SDK use is feasible. Replacing a synchronous Demuxe decoder with an asynchronous SDK decoder is not a direct substitution and must not silently change the current preparation recipe's scheduling or resource policy.

Any wrapper must acquire the already-selected, exactly qualified codec first, copy the original integer sample clock without guessing timestamps, preserve only explicitly represented layouts/precision, and close samples/owners on every failure. Global SDK registrations must live in a controlled disposable module/worker context and must never contaminate native-only capability checks. Constructor-time registration in the core, eager fallback registration and downloading all codecs are excluded by the [adapter design](MEDIABUNNY-PROVIDER-ADAPTER.md).

Sources: existing [audio frame/decoder ABI](../packages/provider-audio/src/packet-decoder.ts), [FLAC encoder contract](../packages/provider-audio/src/flac-encoder.ts), [container preparation composition](../packages/provider-container/src/audio-repair.ts), and the pinned [codec/extension audit](MEDIABUNNY-PROVIDER-AUDIT.md). Upstream source links and archive hashes are in that audit. Runtime comparisons, new decoder wrappers and their complete bindings remain unimplemented; this evaluation does not qualify them.


## Delivery boundary confirmed

The user reaffirmed that these are selective provider changes and that MediaBunny paths delegating to FFmpeg do not need replacement. Retain the existing FFmpeg/mpv providers and individually downloadable codec slices. The possible wrappers discussed above are future evaluation notes, not requirements for this adapter delivery. No FFmpeg-backed extension wrapper or new decoder replacement is part of the current implementation.
