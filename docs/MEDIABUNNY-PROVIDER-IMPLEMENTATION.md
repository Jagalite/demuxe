# MediaBunny adapter implementation evidence

Date: 2026-10-29. This records implementation and test evidence, not a production release approval. The [adapter design](MEDIABUNNY-PROVIDER-ADAPTER.md) remains the roadmap; later phases are not implied complete.

## Implemented owners

- `InspectionOptions.inspector` accepts a Demuxe-owned `MediaInspector` function. `inspectMedia` still normalizes sources, owns validated transport, enforces its budget/deadline and closes owned sources. The default fast inspector remains the default. The adapter returns partial evidence and never establishes subtitle absence from A/V enumeration.
- `createMediaBunnyPreviewProvider` implements the existing preview interface. It supplies represented timestamps, conservative accuracy/fidelity, cancellation, deferred resource retirement and playback contention flags. Application loaders and formats remain explicit.
- `mediabunny-file-preparation` is an alternative complete binding with `browser-prepared` for `native-remux`. `ProviderRuntime` checks source eligibility and both qualified identities before acquisition. It executes verified, self-contained code in a bounded dedicated worker. `NativePlayer` retains load generations, startup checks, seeks, object URLs, retirement and fallback.

The local preparation profiles are **`webm-vp8-video-only-v1`** and **`matroska-vp8-video-only-v1`**, producing WebM: at most 32 MiB, one completely inspected VP8 video track, zero-based monotonic timeline, no rotation, flip or transparency. Requested source track identity is retained. A bounded source/output EBML check retains explicit block/default duration and timestamp-scale truth, rejecting packet-API normalization of authored gaps. Lacing, invisible/discardable blocks, content encoding, additional payloads, nonzero codec delay/preroll/offset, explicit track timestamp scaling and unknown-sized clusters remain outside these profiles. The preparation implementation reparses the complete bounded output before publication and requires exact packet metadata/timing and track configuration/geometry/color/name/language preservation. A finer-resolution WebM regression proves that writer quantization declines the profile instead of publishing changed timing. Encoded packet payload hashes are additionally compared in the browser test. Unsupported variants remain outside this implementation profile.

A distinct `mediabunny-mp4-file-preparation` binding and worker implements `mp4-h264-video-only-v1` and `mov-h264-video-only-v1`. Both produce MP4 under the same bounded complete-single-video envelope. The raw classic `avc1` sample-table check verifies sequential authored durations, sizes and sync identity; nonzero composition offsets, nonidentity edits, fragments, external data references and sample groups decline. An identity edit must span its track's full authored duration at the declared movie time scale. Shared packet-copy and verification preserve source H264 track IDs while translating MediaBunny's internal `avc` codec name.

The [MP4/MOV receipt](../packages/provider-mediabunny/qualification/chrome155-local-avc.json) covers generated 64×48 ten-frame AVC fixtures: two real native-owner attempts, packet hashes/configuration, seek at .5 with a fresh frame at .6, decoded color, unqualified and direct non-acquisition, no other container fetch, and retirement of both workers and all object URLs. These fixtures use the upstream MP4/MOV writer; independent authored sample-table tests cover identity edits and rejection of nonidentity edits, reordering, external references and fragments, but do not independently qualify arbitrary encoded MP4/MOV files.

The same MP4 worker adds `mp4-h264-aac-av-v1` and `mov-h264-aac-av-v1` for one video plus one AAC-LC audio track: 48 kHz, mono/stereo, exactly 1024 samples per packet, zero-based timelines, no nonidentity edits and an explicit two-byte LC configuration without extensions. Its authored `roll` group must match the supported one-packet seek-preroll pattern. Both source and output raw sample tables are checked per track, with global movie duration rounded only to its declared time scale; sample PTS/durations and decoded sample extent remain exact. The existing native startup owner now receives the prepared audio track and performs its existing audio checks.

The [stereo receipt](../packages/provider-mediabunny/qualification/chrome155-local-avc-aac.json) and [mono receipt](../packages/provider-mediabunny/qualification/chrome155-local-avc-aac-mono.json) verify both containers, source IDs, packet/configuration hashes, decoded PCM hashes, 76,800 frames, channel count/rate, seek/fresh video, and positive decoded-audio byte progress after seeking. Their fixtures author 75 complete AAC packets at zero and retain encoder priming; this is evidence for preserving that authored source, not removing encoder delay or qualifying trimmed/padded edit lists. Video-only fixtures continue to pass against the upgraded identities. Audio-only and other rate/layout/configuration profiles remain open.

Bounded remote-file preparation is connected to the existing native owner through `ProviderRuntime.prepareRemote`. It admits only an inspected file identity of at most 32 MiB, with a strong ETag or the existing immutable contract, and the same finite format/track guards. The main thread uses the existing `RangeReader`; the optional worker receives no source URL, headers or refresh function. A bounded read channel serializes A/V requests, retains owned buffers and rejects late or malformed results. Source policy snapshots are checked before starting and before publishing; a policy mutation is `SOURCE_CHANGED`. Remote identity/authorization failures retain existing classifications, and cancellation closes transport and terminates the worker.

The [remote MP4/MOV receipt](../packages/provider-mediabunny/qualification/chrome155-remote-avc-aac.json) covers actual native-owner A/V preparation/startup/seek and packet/PCM preservation. It also records changed ETags as `SOURCE_CHANGED`, HTTP 401 as `SOURCE_PERMISSION`, cancellation during worker reads, rejection of mutated admission policy, no credentials in worker messages, direct/unqualified non-acquisition and complete worker/URL retirement. Remote WebM/Matroska cases are recorded alongside the existing VP8 receipt. These are bounded complete-file outputs; incremental segment delivery and streaming backpressure are not implemented by this bridge. The browser composition harness invokes the real native owner directly; it does not claim full public-player release qualification. Existing public plan admission retains its isolation/MSE policy, and remote complete inspection still uses the maintained inspection owner before provider admission.

When a qualified FFmpeg alternative is available, its baseline preference remains. Explicit provider preferences can select MediaBunny after eligibility. Acquisition/integrity failures remain terminal; they are never converted to absence. Required subtitle/gain compositions are not silently assigned this video-only binding. FFmpeg/mpv assets, bindings and codec slices remain in place.

## Remote incremental transport

The separately qualified streaming binding now accepts the same finite inspected remote MP4/MOV AVC/AAC sources as the complete-file path, up to 32 MiB with pinned size and strong ETag or the existing immutable contract. `ProviderRuntime.canStreamRemote` uses complete source facts and the exact provider/presenter identities; the existing FFmpeg/complete-file preference rules apply. `NativePlayer` sends the source to the existing remux producer factory, whose reopen on seek obtains a new validated lease.

`streamRemote` owns `RangeReader` and source policy on the main thread. A private worker bridge carries only size/track facts and exact owned byte ranges. It limits pending requests to eight, total requests to 4096 and logical bytes to 64 MiB per generation. The higher logical budget permits finite metadata/preflight and packet passes over the at-most-32-MiB representation. Each read is bounded to 30 seconds, including queue time; idle playback has no whole-operation timeout. RangeReader retains its own HTTP validation, deadlines, retries and authorization refresh. Source snapshots are checked before and after byte requests, between HTTP blocks and before forwarding producer output.

The bridge consumes read RPC internally and forwards only presentation messages. Original main-thread errors survive without worker serialization. On cancellation, source failure or retirement, transport closes before worker/URL retirement; late read replies cannot publish. Policy mutation fails as `SOURCE_CHANGED`, including during multi-block reads. An ETag change on seek/reopen fails through the real native owner.

The [remote stereo receipt](../packages/provider-mediabunny/qualification/chrome155-remote-native-stream-av.json) and [mono receipt](../packages/provider-mediabunny/qualification/chrome155-remote-native-stream-mono.json) and the corresponding [MOV stereo](../packages/provider-mediabunny/qualification/chrome155-remote-native-stream-mov-av.json) / [MOV mono](../packages/provider-mediabunny/qualification/chrome155-remote-native-stream-mov-mono.json) receipts cover generated AVC/AAC files that cross HTTP blocks, native MSE startup, seek 1.25/fresh frame 1.3, fresh decoded audio, denied access, authorization refresh, cancellation during worker reads, policy mutation, identity failure on reopen, and full worker/URL retirement. The separate finite in-process drain of the same producer compares packet and PCM hashes/614,400 authored audio frames; it is not remote worker packet-hash evidence. Their receipt counters capture successful presentation before intentional failure cases reset the owner. These are actual Runtime/NativePlayer composition tests, not full public-player release qualification.

Eight new core bridge tests exercise owned buffers, privacy of RPC, original error retention, late replies, malformed/duplicate/excessive reads, per-read timeouts, retirement, source failure during handler handoff and secondary cleanup failures. An additional transport test stops a multi-block read on source-policy mutation before another HTTP block starts. Three optional-worker tests cover borrowed byte requests, close while a reply is pending and incomplete response rejection. The [local regression receipt](../packages/provider-mediabunny/qualification/chrome155-local-after-remote-stream.json) passes against the same final worker and updated main-thread owner. The complete-file remote bridge remains available and still returns a Blob.
