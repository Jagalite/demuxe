# Functional core deterministic replay boundary

This inventory defines the finite local architecture gate. It does not grant browser, media-output, performance, package, or release qualification. Production sanitized diagnostics deliberately omit private payloads and cannot reconstruct an exact run. The separate test-only `demuxe-test-replay` version 1 artifact contains complete synthetic action/schedule inputs, normalized transition DTOs and observations for its declared fixture. `replay-artifact.mjs` rejects unsupported versions, unknown action payloads, noncausal schedules and histories beyond 512 actions or 1 MiB. Replay executes only simulated effects. Its expected DTO stream is verification data, never an instruction to execute an external action.

## Mutation and reduction scope

The maintained mutations remove identity retirement, admit a premature source, omit setter rollback, drop pause retirement, issue a preview route change and skip resource release. Each is required to fail its matching contractual test. These are behavioral output/adapter mutations, not a source-code mutation-testing score. The composed shrinker deletes actions only when causal validation remains valid; it proves one-deletion minimality when its explicit trial budget is not exhausted. It does not claim a globally shortest counterexample.

## Reviewed exclusions

- Exhaustive exploration of the entire product of all routes, payloads, settings, workers and unbounded external schedules is not a finite gate. Exhaustiveness is claimed only for the operation and two-owner lease bounds above. Larger domains use maintained adversarial fixtures, deterministic longer histories and coverage of their named contracts.
- The exact replay artifact is synthetic and fixture-versioned. It does not replay production sanitized trace omissions, private URLs, media bytes, tokens, provider instances or browser objects.
- Browser permissions, event-loop nondeterminism, actual audible/visible advancing output, decoder compatibility, package installation and allocation/performance measurements require the separate supported-browser/package qualification matrix. A successful local replay is not evidence those gates passed.
- Liveness assumes a fair closure: issued physical work eventually settles, reaches its declared deadline, or is logically retired; physical work ignoring cancellation may remain explicitly detached until its late result. Logical retirement alone never proves physical resource release.

Changes to the supported contract should update its owning suite and this inventory. Merely adding seeds or aggregate test counts does not expand a reviewed domain.

The combined focused run passes 340 tests in approximately 21 seconds. New suite `player-policy-sequences.mjs` is registered in the core gate; media histories are part of the existing `player-media-simulation.mjs` suite. Failures print replay seeds and bounded recent action histories. Receipt: `results/api-stability/policy-review-2026-10-03/result.json`.

This is adequate as a focused regression layer for the migrated policy contracts. It is not a substitute for real-browser tests that load actual video, execute route construction/fallback and verify presented media, nor for A/V/memory endurance. Those remain qualification gaps; increasing virtual days alone would not close them.

## Adversarial overlapping operations and actual route transactions (2026-10-03)

Added three core-gated suites: `player-route-adversarial.mjs` (39), `settings-adversarial-sequences.mjs` (35), and `startup-adversarial-sequences.mjs` (26). Extended media simulation by 15 cases. Unlike the earlier media fixture, the new route fixture executes production selection/discovery/replacement/acceptance, so the previously documented transaction-integration gap is now partially covered. Its probe/admission/backend boundary is still synthetic; this does not validate actual codec admission or decoding.

New sequence coverage: 648 overlapping media commands under normal/zero/jitter timing; 384 public settings commands with independent accepted/physical-value checks; late callbacks across Close/reopen; partial failure/compensation and degradation; method-getter retirement; timeout/destroy at fetch/read/compile; saturation/retry; and delayed physical cleanup. Route fixture teardown checks every created session was destroyed and removed exactly once with no retained resource/transaction ownership. Failure reports include seeds, command histories or bounded route traces. Ignoring physical Pause is detected by a negative control.

The campaign found three additional defect classes and fixed them. The combined focused run passes 479 tests in approximately 2.2 seconds; see `results/api-stability/adversarial-sequences-2026-10-03/result.json`. Remaining gaps are actual browser/media/provider behavior and endurance, not an absence of route transaction integration tests. No universal/exhaustive correctness claim follows from these bounded campaigns.
