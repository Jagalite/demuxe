# P2.3: remaining configurations in existing audio slices

This work extends existing codec families. A codec name in FFmpeg's configured decoder list does not qualify every mode, rate, channel mask, transport, or seek strategy. Remaining P2 work stays open until its own packet proof, finite provider offer, public routing where applicable, and installed conformance evidence pass.

## Source support and explicit unsupported cases

The pinned source is FFmpeg n9.0.2, locked by `sources.lock.json`; current bridge and public profiles deliberately accept smaller envelopes.

- `libavcodec/amrnbdata.h`: eight ordinary NB frame payload sizes, plus SID. `amrwbdec.c`: ordinary WB modes 0–8; SID is not implemented. One storage TOC byte must have quality 1 and zero reserved bits, with exact mode-owned payload size. DTX/no-data and concatenated frame payloads are excluded.
- `libavcodec/wmalosslessdec.c`: accepts 16/24-bit precision and defines `WMALL_MAX_CHANNELS=8`. This is source support, not eight-channel production qualification.
- `libavcodec/mlpdec.c`: mixed-rate channel groups are unsupported. MLP 7.1 is excluded by the maintained pinned mapping/encoder path; mono proof cannot justify surround remapping.
- `libavcodec/dca_exss.c` reads an explicit sampling-frequency table index and channel assets. DTS-HD admission must preserve the actual full decoder integer precision and original native layout, not infer a mask from channel count.
- Floating speech conversion remains subject to the existing exact FLAC precision guard. Any intentional quantization API is a separate product contract.
