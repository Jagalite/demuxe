# Application API extensions

These APIs extend the existing Player owner and immutable state. Unsupported route operations reject with `UNSUPPORTED_FEATURE`; missing metadata or measurements remain unknown. See the [roadmap validation report](../results/api-roadmap/20260927/README.md) and [follow-up review](../results/api-roadmap/review-20260927/README.md) for exercised paths. This contract does not qualify new codecs, HDR output, or performance.

## Source acceptance and inspection

`open(source, {startTime, signal, trackPolicy, demuxer})` accepts Blob as well as existing inputs. `startTime` is finite nonnegative seconds within a finite VOD duration. The candidate seeks and verifies readiness before acceptance; failure/cancellation preserves the previously accepted source. It is not a frame-exact guarantee. Caller cancellation detaches at source acceptance as before.

`inspectMedia(source, {signal, assetBase, maxBytes, maxReads, timeoutMs})` uses the existing fast metadata parser without a player, audio output, or decoder session. Defaults are 512 KiB returned bytes, 32 provider reads, and 10 seconds; ceilings are 512 KiB, 128 reads, and 30 seconds. The parser also retains its own lower work limits. `completeFor` identifies observed container/track/duration coverage; `complete` does not mean exhaustive tags, chapters, codec support, or playback qualification. Unknown track inventory is null. Inspection IDs are independent of later Player track IDs. Adaptive manifests are not file-inspection inputs. Remote files use the existing RangeReader policy; returned-byte counts are not network-throughput measurements or network-overfetch counters.

Custom sources declare `{kind:'bytes', transport:'application-managed', id, size, read(offset,length,signal), ownership?, close?, name?, type?}`. The `id` must identify immutable bytes, and `size`/offsets must be safe integers. Reads return at most the requested Uint8Array length; nonempty short reads are continued, and premature EOF is a source change. Calls are serialized, limited to 256 KiB per provider request, and have a three-second deadline. Cancellation prevents late publication. Provider failures, permission denials, identity changes, and premature EOF reject inspection; they are not reported as ordinary incomplete metadata. Forward-only providers are not accepted.

The explicit application-managed transport declaration means the provider owns its network authorization/origin policy; Demuxe cannot audit arbitrary callback I/O. Use RemoteSource when Demuxe should enforce that policy. Ownership defaults to borrowed; owned providers have `close()` called when the operation releases them, with bounded cleanup.

Custom playback currently **stages the entire source, up to 32 MiB**, into an independent File before candidate opening. It is not a lazy worker adapter and cannot start playback while staging. Larger sources can be inspected through bounded random reads, but playback requires a File or RemoteSource. Staging does not bypass route admission or prove Native Direct compatibility. This limit is exported as `CUSTOM_SOURCE_PLAYBACK_LIMIT`.

## Metadata and attachments

`state.mediaInfo` now includes reported video tracks, chapters, source tags, color metadata, and coverage for chapters/tags. Tracks include sample rate, channel layout, frame rate, bit depth, profile, roles, and attached-picture status where reported. Null means unreported. Color values are reported source/decoder metadata, not proof of HDR presentation. Inventories reflect the active backend's observations and are not universally exhaustive on Native Direct.

mpv metadata enrichment reads at most 256 chapters and 128 tags, with a 1.5-second scheduling budget between queries. A started query retains its bounded backend RPC deadline. Partial lists are explicitly marked; negative preroll starts are clamped to zero, original chapter ordinals are retained, and chapter ends are derived from the next start or known duration. `seekChapter(id)` rejects stale/unknown source IDs, including when a queued source replacement completes before the chapter seek executes. Native routes without chapter observations return null.

`attachSubtitle(file, options)`, `attachTextTrack({src,label,language?,default?})`, and `attachFont(file)` return immutable opaque handles. Keep the actual returned object; fabricated, serialized/reconstructed, and other-player handles are invalid. `removeAttachment(handle)` preserves unrelated identities. Removing a selected subtitle turns subtitles off when policy permits; a lock or forbidden off state rejects removal transactionally. Browser text attachments are bounded to 16 per source. Shaka accepts plain WebVTT attachments through its owned text pipeline and source network policy; ASS/bitmap attachments remain ineligible on manifests. Subtitle handles expire on new-source acceptance/close; font handles persist across close/open. Both expire on removal/destruction. `addSubtitle`, `addTextTrack`, and `addFont` retain `Promise<void>` compatibility wrappers.

## Timing, styling, seeks, and repeated playback

`setSubtitleDelay(seconds)` and `setAudioDelay(seconds)` accept -60 through 60 seconds; positive means later. Requested values persist across close/open and eligible route changes. Their effective state is null without an accepted source. These controls currently require Hybrid/Software mpv; automatic routing may switch, while an explicitly pinned Native route rejects unsupported settings.

`setSubtitleStyle({fontSize, color, borderSize, fontFamily})` replaces the plain-text style settings. Font size is 8–150, border size 0–10, color is hex RGB/RGBA, and family is at most 128 characters. Authored ASS overrides remain disabled. Bitmap subtitle styling and arbitrary renderer options are not provided. An empty object resets the style on the next transactional replacement. `getTimingSettings()` and `state.timing` describe requested/effective controls and scope. Semantics follow the [mpv timing and subtitle options](https://mpv.io/manual/stable/).

`seek(time, {signal, policy:'queue'|'latest'})` retains queued behavior by default. A latest-policy seek cancels the previous latest-policy request; its promise rejects with `ABORTED`. Cancellation can occur after a backend has moved its clock and does not promise to restore the previous seek position. It cannot publish a replacement source.

`setPlaybackRange({start,end}|null)` restricts seeks and playback to an observed seekable interval. `setLoop(true|false|{start,end})` repeats the whole finite source, active range, or an A–B interval. Setting an A–B loop from outside its interval first seeks to its start. Queued boundary handling rechecks the current range and source before acting. These settings are source-scoped and reset on replacement/close. End detection follows observed clock updates, so boundary overshoot and restart gaps are possible; this is not sample-exact or gapless playback. The core owns repeats and suppresses a terminal ended event for a loop; the component queue does not become a second loop owner.

`stepFrame(1|-1)` pauses and asks the mpv video route to present an adjacent frame. It rejects Native, absent video, or an unpresentable step; backward stepping may decode from an earlier seek point. A 25-second deadline bounds verification. It does not promise constant frame duration or universal backward support.

## Streaming quality and live navigation

`getStreamingState()` / `state.streaming` return null on ordinary file routes. Qualities have source-scoped IDs and are filtered against selected audio and immutable source constraints. `setQuality({mode:'auto',maxHeight?,maxBandwidth?})` controls ABR; `{mode:'manual',id}` selects one available variant. It never widens a source ceiling or removes a source pin. Rejected configuration or ignored manual selection fails without publishing the requested policy. Selected audio remains part of the constraint. A runtime manual pin selects an exact audio/video variant, so an incompatible audio-track change rejects; return to automatic quality before changing that audio choice. Manual IDs are not guessed equivalent across replacement backend sessions: such replacements reject while a runtime manual pin is active. Return to eligible automatic policy before switching routes.

Requested policy, backend-selected ID, observed quality at Shaka's buffered playhead, and presented-frame identity are separate. Presented ID remains null because the adapter cannot prove frame-to-variant identity; transition state stays unknown. Observed quality includes its position/content type and `playhead-buffer` provenance. These fields must not be used as proof of an exact displayed rendition. See [Shaka's quality and live API](https://shaka-project.github.io/shaka-player/docs/api/shaka.Player.html).

`seekToLive()` delegates target choice to Shaka's live navigation and verifies the seek through Native. It requires explicit live-source permission and an actual live timeline. Near-live means within two seconds of the backend's recommended seek endpoint; latency uses an available playhead-to-date mapping and is otherwise null. Route selection, streaming quality, and software `decodeQuality` remain independent policies.

## Statistics and playback explanation

`getStats()` returns a frozen snapshot. Source-scoped counters reset on new-source acceptance/close; `sessionEpoch` increments on accepted route replacement. Timings use the monotonic performance clock. Open-to-acceptance excludes time waiting in the control queue. First-playing latency observes normalized playing status, not first-frame presentation. Rebuffer duration/count begin only after initial playing, exclude pending operations and pause, and include an ongoing observed interval. Seek latency/count describe successful seeking operations (including core range/loop navigation). Unobserved frame and throughput counters are null.

`getPlaybackExplanation()` exposes accepted plan/component identities, automatic-selection intent, decode-quality policy, up to 64 recent selection attempts, typed admission rejection codes, and nullable backend-reported effective decode fidelity. Admission decisions are observations from the latest selection evaluation, not proof that every eligible plan has run. Existing advanced diagnostics remain available and redacted. No CPU percentage, total-memory claim, hardware-decoder claim, or fabricated throughput is added.

## Browser presentation and snapshots

`player.presentation` offers fullscreen, video/document PiP, and explicit Media Session ownership. Browser permission and gesture requirements still apply. Video PiP requires a Native video without separate subtitle composition; surface replacement is rejected while it is active or entry is pending. Subtitle activation and attachment also reject while video PiP is active or pending. Concurrent PiP entry requests reject; exit/destruction retires late entry completions. Document PiP moves the core presentation container, retaining its surfaces/overlays, and restores it on window close. External application controls are not automatically moved into that container. Media Session is opt-in; a second player must wait for the current owner to release it. Destruction releases owned presentation state.

`setAudioOutputDevice(id)` selects the actual media-element or AudioContext sink where the browser permits it. The ID persists across qualified replacements. Both `default` and the empty string select the system default. Permission denial is explicit; unavailable sink APIs reject. It does not enumerate devices or request chooser permission implicitly.

`snapshot({width?,height?,includeSubtitles?})` returns encoded image bytes and observation metadata. Native snapshots use bounded canvas readback and can fail due to source/CORS restrictions; Native subtitle composition is not qualified for capture. mpv uses its current presentation size; embedded subtitles cannot be removed from that surface. `actualTime` remains null; `mediaTime` is an observed clock value, not a verified captured PTS. This API is separate from independent timeline previews.

Frameworks can subscribe to the same immutable state and await core teardown. React applications can use `useSyncExternalStore(player.subscribe.bind(player), () => player.state)` with a host-provided SSR snapshot; framework dependencies are not loaded by the core. Global media/presentation ownership remains explicit with multiple mounted players.
