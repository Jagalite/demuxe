This beta uses the reduced qualification scope below. Publication requires a passing `reduced-qualification.json` receipt for the exact package; that receipt records the final revision, artifact hashes and gate results. The historical Chrome cleanup observation is accepted as a documented uncertainty after the final single-attempt check passed.

The registry currently publishes beta.5 from source 67117b12. This candidate includes the functional-core work plus the newer player controls. ## Changes

- Retain player source-control, autoplay, preview-label and timeline-targeting updates from fbd15d49.
- Preserve keyboard focus on timeline or volume when asynchronous autoplay completes.
- Hide controls immediately for keyboard seeking during playback, with timeline-only seek feedback. Paused playback, dragging, focused sliders and open menus retain their existing control behavior. The dedicated keyboard suite exercises all 16 seek shortcuts and four interaction guards using a loaded video.
- Retain the native event-wait timeout cleanup already included in qualification commit 68bbb450.
- Fix selective PCM startup when native audio initialization publishes its epoch after the play command resolves. Only the active first-timestamp lease may authorize a stable, acknowledged epoch; the original three-second deadline remains.
- Measure temporary seek feedback inside the browser so host RPC delay cannot move the observation beyond its lifetime. Missing and never-expiring feedback are separately negative-tested.
- Advance player/core metadata to beta.6 and derive default test archive names from package version.

## Outstanding evidence

Chrome's original worker-cleanup failure remains unexplained. On October 4, 2026, the user accepted this documented uncertainty after one final check, so it is no longer a release blocker by itself. The consumer test keeps its original two-second zero-worker gate, now makes one attempt, and retains bounded lifecycle and liveness diagnostics on failure. Three additional exact-workload trials, 48 browser ownership-ordering cases, and eight same-page mode/source churn cycles passed. Tracing all root workers in the exact workload confirmed destruction and termination of all three software-worker instances, including earlier retired sources. A Playwright protocol model demonstrated a conditional missed-detach bookkeeping path, but browsers did not reproduce that ordering. None of these passes establishes the historical Chrome cause. The final full Chrome consumer run against the frozen archive passed 8/8 checks without retries. All four application destruction checks found zero workers, and creation/closure counts matched. The receipt is `results/public-api-consumer/chrome-2026-10-04T13-57-37.926Z/result.json` (SHA-256 `b636eba0` prefix); it validates the final investigation, not the final beta.6 archive.

The WebKit activation test used an invalid early assertion: it required hiding within 1.5 seconds while native public-play verification could still be pending. The replacement observes hiding at actual public-play completion and establishes independent playback preconditions for subsequent checks. A focused test reproduced the original awaited-input then 1.5-second Playwright-wait ordering: the wait timed out, and the same Space-initiated request completed at 2.41 seconds with playback and hidden controls. The native verification budget was unchanged. The historical interrupted request cannot be retrospectively verified; no native hang or runtime fix is claimed.

A separate K trial recovered through fallback but its diagnostic kept observing the retired video. It is retained as a failed diagnostic, not a passing output check. The maintained observer follows the current playback session and separates immediate control hiding from eventual playback-state and clock observations: command completion does not guarantee that every backend's playing notification has already arrived. A focused recovery test then passed with the corrected observer: native verification timed out, playback recovered onto a replacement video, and the public state and clock advanced about 208 ms after completion. The immediate snapshot still reported paused with play intent, so the former instantaneous-status assertion would have rejected successful recovery. Another historical trace recorded a one-second browser scheduling gap across a temporary-preview observation; that timing evidence remains inconclusive.

Focused cleanup/lifecycle checks passed 43/43, the corrected WebKit component run passed 60/60, and the maintained Chrome wiring run recorded 60 worker creations and 60 closures. Delayed real-play completion passed the control-hiding oracle; deliberately missing and delayed hiding failed as expected. Six additional real-video activation sequences passed, including two scheduling-stall cases completing at 2.19 and 2.39 seconds. Those six sequences support the completion-based contract but do not independently reproduce the original Playwright wait ordering. No playback runtime changes follow from this investigation.

Release publication must use the exact archive that passes the reduced gate, with these scope limits and the accepted Chrome observation retained in the release notes. The full release verifier must not be represented as passed.
