# 0.3.0-beta.6 candidate

Status: preparation in progress; publication is blocked until the checks below are complete.

The registry currently publishes beta.5 from source 67117b12. This candidate includes the functional-core work plus the newer player controls. The reduced validation scope compares the player update against frozen candidate f4d7f3fd; it does not imply that the entire difference from published beta.5 is player-only. Historical qualification receipts remain unchanged.

## Changes

- Retain player source-control, autoplay, preview-label and timeline-targeting updates from fbd15d49.
- Preserve keyboard focus on timeline or volume when asynchronous autoplay completes.
- Hide controls immediately for keyboard seeking during playback, with timeline-only seek feedback. Paused playback, dragging, focused sliders and open menus retain their existing control behavior. The dedicated keyboard suite exercises all 16 seek shortcuts and four interaction guards using a loaded video.
- Retain the native event-wait timeout cleanup already included in qualification commit 68bbb450.
- Fix selective PCM startup when native audio initialization publishes its epoch after the play command resolves. Only the active first-timestamp lease may authorize a stable, acknowledged epoch; the original three-second deadline remains.
- Measure temporary seek feedback inside the browser so host RPC delay cannot move the observation beyond its lifetime. Missing and never-expiring feedback are separately negative-tested.
- Advance player/core metadata to beta.6 and derive default test archive names from package version.

## Reduced release gate

The user authorized skipping unrelated requalification but explicitly requires resolution of the observed Chrome worker-cleanup and Firefox PCM-startup failures before release.

Required: build/types and API contracts; focused actual controller/worklet regressions; three-browser player controls and loaded-video sequences; exact archive source/license/integrity checks; offline installation, imports and asset copying; focused Firefox PCM and Chrome cleanup checks.

Deferred: complete codec catalogue reruns, engine rebuilds when all recorded native inputs and binary hashes remain unchanged, CPU/frame-rate comparisons and long endurance. No new performance or format-support claim follows from this reduced gate. The standard full release verifier is not weakened or represented as passed.

## Outstanding evidence

Chrome's original worker-cleanup deadline failure remains unexplained. Controlled diagnostics pass, but those passes do not establish its cause or constitute a fix. Intermittent WebKit activation timeouts also remain recorded; an instrumented component run passes, with no evidence yet supporting a runtime or deadline change. These observations must be adjudicated before claiming release readiness.

Follow-up investigation reproduced a WebKit activation assertion while native public-play verification was still pending. That check imposed a 1.5-second deadline before the public operation had completed. A failure also contaminated the following held-key check by leaving playback running; independent pause setup and cleanup now prevent that cascade. Later traced runs completed verification, but the reproduced failure was interrupted by the next key before its eventual verification result was recorded, so its underlying verification outcome remains unresolved. A separate trace recorded a one-second browser scheduling gap across a temporary-preview observation; it is retained as inconclusive timing evidence.

Three further Chrome bundled/deep-path trials passed the original two-second zero-worker gate and recorded actual worker termination, iframe removal and AudioContext closure. The maintained consumer test now makes one attempt and retains bounded lifecycle and liveness diagnostics on failure, while keeping the zero-worker assertion unchanged. Its wiring run recorded 60 worker creations and 60 closures. These passes do not establish the cause of the original cleanup failure. Focused cleanup/lifecycle checks passed 43/43. The corrected WebKit component run passed 60/60; real-play delayed completion passed its control-hiding oracle, while deliberately missing and delayed hiding both failed as expected. No playback runtime changes follow from this investigation.

The candidate is not authorized for npm publication or a public release tag merely by completing this preparation.

## Keyboard-seek validation

The new loaded-video regression failed all 16 playing shortcuts before the change while its 20 paused and interaction-guard cases passed. With the change, Chrome, Firefox and WebKit each passed all 36 cases. The checks observe immediate control visibility, timeline-only feedback and completed real seek targets; TypeScript compilation also passed. These focused results do not resolve the outstanding release incidents above.

## Dependency lock provenance

The root dependency lock is retained byte-for-byte from the recorded native build. Its informational root version remains beta.4 while publishable player/core package metadata is beta.6. No dependency, resolution, integrity or package-manager input changed. npm does not publish package-lock.json. This deliberately preserves the actual native build input and the unchanged strict archive/source verification gates, rather than rewriting the build record or introducing a provenance exception for cosmetic version metadata. A future dependency-lock regeneration requires rechecking the native build inputs.
