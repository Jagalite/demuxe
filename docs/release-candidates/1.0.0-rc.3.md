# 1.0.0-rc.3 candidate

This v1 release candidate uses the reduced qualification scope below. Publication requires a passing `reduced-qualification.json` receipt for the exact package; that receipt records the final revision, artifact hashes and gate results. The historical Chrome cleanup observation is accepted as a documented uncertainty after the final single-attempt check passed.

The registry currently publishes beta.5 from source 67117b12. This candidate includes the functional-core work plus the newer player controls. The reduced validation scope compares the player update against frozen candidate f4d7f3fd; it does not imply that the entire difference from published beta.5 is player-only. Historical qualification receipts remain unchanged.

The target stable release is `1.0.0`. This candidate keeps the public API contract and compatibility checks as release gates. The accepted historical Chrome observation is not a blocker; its cause remains unknown. Deferred qualification remains explicit and is not implied by the major-version number.

## Changes

- Retain player source-control, autoplay, preview-label and timeline-targeting updates from fbd15d49.
- Preserve keyboard focus on timeline or volume when asynchronous autoplay completes.
- Hide controls immediately for keyboard seeking during playback, with timeline-only seek feedback. Paused playback, dragging, focused sliders and open menus retain their existing control behavior. The dedicated keyboard suite exercises all 16 seek shortcuts and four interaction guards using a loaded video.
- Retain the native event-wait timeout cleanup already included in qualification commit 68bbb450.
- Fix selective PCM startup when native audio initialization publishes its epoch after the play command resolves. Only the active first-timestamp lease may authorize a stable, acknowledged epoch; the original three-second deadline remains.
- Measure temporary seek feedback inside the browser so host RPC delay cannot move the observation beyond its lifetime. Missing and never-expiring feedback are separately negative-tested.
- Fix settings-menu dismissal when WebKit leaves a discrete display transition pending. Closing now removes the menu from layout immediately; opacity, translation and scale entrance transitions remain.
- Advance player/core metadata to 1.0.0-rc.3 and derive default test archive names from package version.

## Timeline clock validation

RC1 completed 14 of 15 reduced-gate groups successfully. Its WebKit timeline test compared a source target of 4.8 seconds with the raw video clock at 5.8 seconds. Native remux intentionally uses a one-second media-clock bias. Focused real WebKit tests demonstrated both direct playback (raw 4.8, bias 0) and remux playback (raw 5.8, bias 1) at the same correct 4.8-second source position. The original failed report lacked route diagnostics, so its route is inferred; the invalid clock-comparison mechanism was demonstrated directly.

The corrected test checks the current backend-owned surface, source identity and media clock mapped to source time. It retains the original 0.15-second tolerance and records the route and bias. All three maintained timeline suites passed against RC1, and deliberately shifted real seeks were rejected on direct and remux routes. This is a test correction; playback code is unchanged. RC1 evidence remains preserved, and RC2 requires its own complete exact-package gate.

## Settings-menu dismissal

RC2 completed 14 of 15 reduced-gate groups successfully, including the corrected timeline tests in all three browsers. Its WebKit component suite failed one outside-click menu dismissal. A bounded reproduction failed on trial five: the trusted pointer hit the video, the menu state synchronously closed, and the hidden attribute was set, but a pending discrete display transition left the panel visibly displayed after the original one-second deadline. No reopen event occurred.

The fix removes only the settings panel's discrete display transition. The regression samples computed display during the same outside pointer event after component dismissal, for both a synthetic heading event and a trusted video click. It failed against untouched RC2 styles. With the fixed style module, focused Chrome, Firefox and WebKit checks passed, the full WebKit suite passed 60/60, and ten fresh-page WebKit cases passed with entrance animations deliberately paused. The original one-second visibility deadline remains unchanged. These focused style-override results establish the cause and fix; RC3 requires its own complete exact-package gate. RC2 and the failed reproduction remain preserved.
