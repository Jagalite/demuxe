# Demuxe 1.0.0

This release uses the explicitly authorized reduced qualification policy. Publication requires a validated `reduced-qualification.json` with status `reduced-stable-tested` and `releaseEligible:true` for the exact `1.0.0` package and `reduced-v1.0.0` tag. The receipt binds the source revision, archive hashes, corresponding source, native build inputs and all required gate results. Stable semantic versioning does not imply that deferred qualification has passed.

## Changes

- Migrate playback decisions and transitions into the functional core while retaining browser and media effects in their hosts.
- Include player source controls, autoplay, preview-label and timeline-targeting updates, plus native event-wait timeout cleanup.
- Preserve slider focus when asynchronous autoplay completes.
- Hide controls immediately for keyboard seeking during playback, retaining timeline seek feedback and the existing paused, dragging, slider and menu behavior.
- Fix selective PCM startup when native audio publishes its epoch after the play command resolves, retaining the original startup deadline.
- Fix settings-menu dismissal in WebKit by removing its discrete display transition. Menus close immediately while entrance motion remains.
- Correct browser tests to observe public play completion, follow the current surface after recovery, and compare media clocks in source time on remux routes.

This is the first stable semantic version. The changes since published beta.5 include the functional-core migration as well as player work. The reduced package correspondence check uses frozen candidate f4d7f3fd; it does not claim that the entire difference from published beta.5 is player-only.

## Required release evidence

All fifteen exact-package gate groups must run: component controls, keyboard seeking and timeline targeting in Chrome, Firefox and WebKit; loaded-video native, hybrid and software playback in all three browsers; Chrome and Firefox independent consumers; CLI asset copying; and Chrome and Firefox PCM audio-tail checks. Public API/build and license checks are also required; their CI results are retained separately from the fifteen-row package receipt. The final outcomes belong in the attached receipt, rather than being predicted by these source notes. Only the specifically accepted Chrome worker-cleanup signature may be admitted as a documented gate exception; all other failures block release. Failed tests retain their failed status.

The WebKit menu regression failed with the old style and passed with the fix in all three focused browser checks, a full 60-case WebKit suite, and ten cases with entrance animations deliberately paused. Earlier RC failures and their diagnostics remain preserved; see [RC3 investigation notes](1.0.0-rc.3.md). Focused checks do not replace the exact stable archive gate.

The first stable-package attempt passed fourteen groups but its Firefox keyboard test compared raw media time with source time: all seek cases showed a one-second offset, while control behavior and public target positions were correct. That report lacked route/bias diagnostics; the route is inferred. Forced Firefox remux testing demonstrated the clock-mapping contract directly. The corrected test records the current source, backend-owned surface and actual timeline bias, retaining the original 0.35-second tolerance and all 36 interaction cases. The maintained suite passed 36/36 in each browser and another 36/36 on forced Firefox remux playback. On both direct and remux routes, shifting the actual media clock by half a second was rejected while public time remained at the target. This changes the test oracle, not playback behavior; the final source-bound archive still requires its own complete gate.

## Accepted finding and deferred scope

The Chrome worker-cleanup issue remains unresolved. Earlier follow-up consumer runs passed all eight checks without retries. RC3 then reproduced the symptom in the bundled application at `/deep/runtime-v2/`: seven consumer cases passed, but one software worker remained reported after destruction. The owning iframe was disconnected, its audio context was closed, and worker creation/closure counts were 60/59. Chrome's target list still contained that worker, while a bounded evaluation probe timed out. This confirms recurrence of the cleanup symptom; it does not establish whether the worker remained executable or identify its cause.

The user accepted ignoring this issue for now and proceeding toward v1. The original two-second zero-worker assertion remains unchanged, with no retry-to-pass behavior. A reduced stable receipt may explicitly admit only this known cleanup failure with matching raw diagnostics, exact archive/source identity, and every other required check passing. It must retain the failed gate and case statuses and record the accepted exception separately. No Chrome cleanup fix or all-green result is claimed when an exception is used.

Deferred checks are the complete codec catalogue, full optional-runtime and streaming/Shaka matrices, CPU/frame-rate comparisons and long-duration physical audio/video playback. CPU measurements were deferred while Blender renders affected the machine. This release makes no new performance, universal format-support, or long-endurance claim.

`fullReleaseQualified` remains false. The existing packager's `beta-candidate-not-production-qualified` and `qualification.production:false` fields remain intact as packaging and full-qualification descriptors; the separate `reduced-stable-tested` receipt records this explicitly limited stable-release policy. The original full verifier is unchanged and is not represented as passed.

## Package and publication provenance

Player/core metadata is `1.0.0`. The dependency lock retains its recorded beta.4 root-version field unchanged, preserving the native build input; dependencies and resolutions have not changed. The package gate verifies all 263 native inputs and native binary hashes against the existing build record, with matching source companions and license material.

GitHub publication and npm staging remain distinct actions; preparing these files does not publish the package. npm staging retains provenance and maintainer approval.
