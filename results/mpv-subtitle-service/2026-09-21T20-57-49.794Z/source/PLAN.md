# Bounded prototype measurement

Compare full Software mpv versus Native incremental remux + externally clocked mpv subtitles in headed Chrome on the same authored 40-second 720p HEVC Main10/AAC/ASS fixture, with no B frames and one-second GOPs. Three fresh-browser runs per arm, alternating order S/C, C/S, S/C. Two seconds warmup from source start, then 12-second windows. Browser-process CPU time via CDP SystemInfo, wall time and actual media progression. One full CPU core is 100%. Require subtitle mask agreement >97%, empty-cue control, zero service A/V chains, clean cleanup, real-time media progression within one second/window, and >20% median CPU reduction for the narrow steady-state decision. New browser for each trial; host workload not controlled beyond not running our other tests/builds during measurement. No confidence interval or energy claim from three trials.

Subtitle seek correctness is component-level using explicit browser-time injection: full combined Native remux seeks currently fail a separate presentation guard and are not qualified. An initial long-GOP no-B-frame fixture stalled after buffer eviction; the comparison is restricted to one-second GOPs. A prior B-frame fixture was rejected by remux for timestamp discontinuity and is excluded, with evidence retained. The prototype stages the complete approximately 8 MiB synthetic file in subtitle Wasm memory; this is not bounded source streaming or large-file qualification. It uses a second mpv demuxer and retains the full linked mpv library, while disabling A/V playback. Native media does incremental remux using the maintained runtime. Startup includes file staging and both engines, except HTML module loading and fresh-browser launch. No full-file pre-remux.
