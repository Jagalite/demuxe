## Shared runtime baseline

The cached FFmpeg n7.1.1 archive matches `sources.lock.json`. Emscripten reports 4.0.14. The maintained adaptation builder created fresh patched sources, objects, libraries and compiler cache under `build/local-screening/adaptation-reference`. The verifier checked 8,563 preferred-source files, library/artifact hashes, ABI 2 and the exact decoder/encoder inventory. The maintained remux linker reused those same immutable libraries with adaptation disabled at the bridge. This is a research build sharing compatible dependencies, not a release build or the historical packet-only configuration qualification.

All six original FLAC cases passed: S24, B frames, nonzero starts, unequal ends, audio offset and selected S16 mono at 44.1 kHz. The oracle checks complete decoded PCM against the input, selected video packet hashes, counts, relative PTS and monotonic DTS. Nine lifecycle controls pass for the R47 candidate, including changed ETag, injected late-generation fragment, cancelled blocked read, invalid ranges, distant/buffered seeks and unsupported precision/layout. A valid half-amplitude FLAC output with the same decoded sample count is rejected by the exact PCM oracle (`runs/engine-baseline/wrong-output-control.json`). This is a post-capture fault, not a physical speaker test.

B0 and B1/B2 now have narrow Chrome/local and authenticated-range evidence; none establishes release qualification, opaque browser audio fidelity, Safari/mobile, or B3 ASS. The source SDK is reused read-only; its mutable cache is isolated in this campaign. No historical experimental binaries were substituted.

## Rank decisions and code boundaries

1. **R74 — complete-playback gate not met after reopening.** Short fixtures were below the initial effort gate, but the 30-second S24 observer crossed it (6.779% of worker remux elapsed time). A packed-only research bypass subsequently passed five exact-output cases, nine lifecycle cases, two FIFO source-overwrite controls and invalid-low-bit rejection. Seven alternating full-playback CPU pairs then measured −0.80% aggregate saving, with an approximate paired 95% interval of −2.97% to +1.23%, below the declared 5% worthwhile gate. The candidate remains isolated, not promoted. See `follow-up.md` for scope, sources and accounting limits.
2. **R40 — no opportunity in maintained slider handling.** `src/player/index.ts` updates the preview on `input` and seeks on `change`; 81 alternating preview events produced no backend seeks and the final commit produced one seek at 7.3 s. `Player.seek()` remains an exact queued public operation and must not silently acquire scrub semantics.
3. **R01 — duplication confirmed; ownership work re-estimated.** `web/source-probe.js` owns and terminates a reader and probe worker. Playback creates new owners in `web/native-remux-player.js`. Each ordinary traced startup read 277,304 identical range bytes in both reader owners (954,608 bytes across both owners during the short trace). Same-source `sourceInspection` already reuses metadata for admission. Reusing deeper results requires a bounded source-specific handoff across these owners, not omitting validation or caching by URL. Cold setup/copy/retention cost and cross-consumer cancellation remain unmeasured, so no optimization win or broad broker is justified.
4. **R02 — existing direct promotion.** `src/unified-player.ts` accepts the prepared candidate and later plays that same backend/surface. The browser identity check passed. Fallback/preparation across different engines remains a separate R01-style ownership question.
5. **R242-A — identity unresolved.** Exact `R239-R246-report.md` bytes are missing; no substitution from another R242.
6. **R27 — paired maintained-baseline screen remains inconclusive.** Compilation/body/instance costs are now separated. A one-module prototype shares immutable code across fresh engines and passes cold/repeated/concurrent starts, abandoned shared preparation, source change and cleanup. Seven alternating pairs against the unchanged worker measure 14.10% aggregate startup-suite saving, but the approximate 9.89–18.39% interval crosses the declared 10% value gate. No production cache is integrated. See `follow-up.md` for the preserved decomposed-hook control, no-store development-server condition and remaining ownership/cache qualification limits.
7. **R48 — capability observed, integration deferred.** `NativePlayer.addTextTrack()` creates a browser-owned URL track, exposing the browser's complete cue list. Ordinary and large cases retain 21 and 10,001 cues, with overlapping/long cues and backward seeks checked. Recorded loads were 2.79/21.61 ms in a diagnostic run, not paired performance results. Moving to an application window adds parsing/authority/lifecycle ownership and changes exposed list semantics. The follow-up exact-boundary test matches an independent plain browser video/track; the original exclusive-end oracle disagreed with this Chrome behavior. A separate micro-seek diagnostic records the existing 1 ms seek tolerance. No virtualization patch is justified without that contract and oracle work.
8. **R04 — no material publication wait in sampled path.** `emit_bytes` copies owned spans; synchronous `rm_step` returns before worker publication. The real trace has 27 emissions, 25 batches and 1,042,098 bytes. Most first-emission-to-flush intervals are <=0.025 ms; header and final tail were 1.895/0.585 ms. These times include observer overhead. Larger native steps could reopen this, but subdividing existing mux fragmentation is outside this screen.
9. **R47 — promising owned-buffer survivor.** `native-remux-worker.js:flush` gathers every batch even when `emit_bytes` supplied one full owned ArrayBuffer. The research variant reuses only that full non-shared buffer. Partial views, shared buffers, multiple pieces and empty batches preserve independent assembly. It avoids 1,002,511 of 1,042,098 gather bytes (96.2%), retaining 25 appends and exact 360 video/564 audio packet hashes. Four adaptation cases and nine lifecycle cases pass. See `r47-single-owned.patch`, ownership tests and endurance evidence. The 100-cycle/30-minute local profile subsequently passed and the same worker is integrated; see `r47-qualification.md`. No CPU gain is claimed.
10. **R42 — no demonstrated residual allocation bottleneck.** This workload emits 27 owned pieces in 12 seconds and retains at most one pending batch. R47 avoids 23 gathers without a return channel. A pool still requires bounded generation-aware return ownership and changes the native emit/worker/append protocol. This trace provides no GC or allocation-pressure reason to add it; reopen on a measured high-rate workload. R47 does not prove pooling is universally unnecessary.
11. **R34 — no observed partial producer schedule to optimize.** The current source delivers 25 complete batches, not the report's artificial 89-piece trickle. Adaptive splitting would add sequencing inside a complete available buffer; a benefit is not established by the earlier standalone lab. Reopen on actual delayed partial delivery or excessive append frequency with identical production samples and schedule.
12. **R09 — existing cheaper direct route.** A newly generated fragmented H.264/AAC MP4 opens, presents and seeks through `native-direct`. A new MSE parser/pass-through service is unnecessary for this local source. Controlled-fetch or selected-track sources that cannot use direct playback remain separate inputs.
13. **R131 — identity unresolved.** Missing `R116-R131-report.md`, not the later representation-search proposal.
14. **R274 — identity unresolved.** Missing `R268-R275-report.md`; no index generator is assumed.
15. **R72 — missing service, E3.** No maintained storyboard/coarse decoded-preview API exists in `src/types.ts`/player. `seek-preview` is control visibility, not thumbnail decoding. Building a preview service is beyond a localized keyframe screen.
16. **R73 — missing service, E3.** No pending exact-thumbnail service or persistent preview decoder exists. Historical process-per-request wins do not qualify production sharing. Reopen only with that service and a real request workload.
17. **R272 — identity unresolved.** Missing rectangular-copy source report. Existing decoder workers already use `frame.visibleRect` in some copy paths, but that alone cannot resolve the exact requested ROI mechanism.

## Real-media extension

Existing Big Buck Bunny excerpts were copied from the local maintained fixture cache only after their recorded hashes matched. Original media was not modified. Attribution: (c) copyright 2008, Blender Foundation / www.bigbuckbunny.org, CC BY 3.0; see `docs/MEDIA-NOTICES.md`. Source commands and hashes are preserved in `runs/engine-baseline/bbb-manifest.json` and `bbb-key-manifest.json`.

The non-keyframe-aligned `bbb-060.mp4` excerpt fails in the **unmodified** forced-remux reference at `rm_step` with FFmpeg -68. It passes Native direct opening, output and seeking. The follow-up diagnostic establishes the existing deep-preroll guard as the cause: a -7.933333-second first DTS exceeds the one-second mux bias. It remains a baseline limitation, not a candidate regression or a source to silently re-encode for success.

The keyframe-aligned 1080p `bbb-key-060.mp4` passes reference and candidate remux. All 782 video and 1,220 audio packet hashes match the input; complete captured reference/candidate MP4 bytes are identical, as are all 53 append sizes. Gather-copy reduction is **8.96%**, below the predeclared 25% value threshold for that workload. The earlier **96.2%** is specific to the small-fragment synthetic fixture and must not be advertised as a general movie improvement. These are copy counts; neither result establishes lower total CPU or latency. This real-media control adds correctness coverage, not a second value-qualified workload.

The R01 read trace counts application File reads, not physical disk I/O. Operating-system caching and the cost of retaining/transferring cached ranges remain unmeasured. The file connector could not retrieve missing reports because it is not connected; no claim is made that the files are absent from that external account.
