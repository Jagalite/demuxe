## Hypothesis and requested output

The test applies PNG filter type 4 (Paeth) to controlled RGBA scanlines. A checkpoint stores exactly the prior reconstructed row every 32 rows. Every queried band reconstructed from the nearest checkpoint was byte-identical to replaying from row zero. The durable result is dependency-work reduction (71.5%), not the Python timing itself. This begins after compressed bytes have been inflated; ordinary PNG DEFLATE still needs its own seek/checkpoint strategy before this becomes a file-level ROI decoder.

Exact integer planes or an explicitly defined numerical/altered-output contract; compare the final requested region and later references where relevant.

## Current opportunity and decision

Current byte readers do not expose inflated PNG rows or a PNG filter decoder. Prior-row checkpoints reduce post-inflate Paeth replay only; ordinary compressed-file random access still needs independent inflate state.

## Cheapest baseline

Current checkout behavior at cited owners; historical report bodies inform the comparison but their raw runs were not revalidated.

## Bounded next test and falsifier

On already-inflated rows, compare band reconstruction with checkpoint versus row-zero replay and changed-prior-row rejection; account separately for full-file inflate.

Adverse control/falsifier: Change stride, crop, phase, alpha, edge neighborhood or resource generation; exercise a case where the proposed shortcut is ineligible.

## Reopen condition

Reopen when a PNG ROI path exists or inflated row reuse is requested; do not advertise file-level random access from row checkpoints.
