## R82 — Browser-side video normalization

The exact proposed WebCodecs path cannot run on the permitted page because `VideoEncoder`/`VideoDecoder` are not exposed. A fallback experiment used browser-native H.264 playback as the decoder, `canvas.captureStream()` as the frame bridge and `MediaRecorder` as the browser encoder.

Three runs produced **89–90 source frame callbacks** from a 90-frame source. Median generated size was **276,085 bytes**, versus **146,513 bytes** for the source. The generated VP9/WebM appended successfully to an MSE `SourceBuffer`, supported a seek to 1.8 s and reached EOF. Median MSE duration was **3.032 s** for the 3.000 s source.

The result is not a transparent normalizer yet. Nearest-frame comparisons usually matched the generated frame to a source frame about **2 frames earlier**, and downscaled RGB mean absolute error was roughly **4–5/255** at the sampled points. This proves a browser-only decode→encode→MSE loop, but also exposes timeline control as a first-class problem. A secure-context WebCodecs test should use explicit input/output timestamps rather than inheriting MediaRecorder's realtime clock.

## Opportunity and first-pass conclusion

Current browser bridge decodes chunks but no VideoEncoder/normalization mux queue exists. The report's MediaRecorder fallback has frame/timing differences and is not a transparent candidate.

Contract: Explicitly declared normalization fidelity, exact timestamp mapping, required audio and full duration; no silent frame omission.

Cheapest correct baseline: Explicit-timestamp reference normalization preserving the chosen fidelity contract and source duration; original playback is the input oracle.

Primary outcome: a faithful additional capability or removable current work; no local performance measurement was made.

Bounded next test: Scope one secure-context VideoDecoder-to-VideoEncoder timestamp harness on tiny identified frames with explicit output contract before any player adapter.

Falsifier/adverse control: Missing final frame or shifted timestamp must fail even if generated file appends and reaches EOF.

Reopen: the specifically missing adapter, representation or observed capability in the next test becomes available; a report from a different environment alone does not satisfy this gate.

Limits: source report observations are historical assertions only; raw historical runs were not imported or rerun. This verdict is per mechanism identity, not a family-wide failure.
