## R263 — retained deep samples / deferred composition

Three synthetic 384×384 deep frames with 1–6 samples/pixel were displayed through 36 sparse 96×96 viewports. The eager baseline flattened the full frame for every view; the deferred route composited only the requested deep ROI.

**Result.** Maximum absolute output error was **0.0**. Median CPU time fell from 0.498s to 0.034s (14.8×) for this sparse-viewport workload.

**Blocked gate.** Chromium reports WebGPU=false, WebGL=false, WebGL2=false in this environment. This proves the retained/deferred algorithm on CPU only, not the intended GPU presenter. No OpenEXR/deep-image parser or real deep sequence I/O was exercised.

## Bounded decision

Hypothesis: The mechanism 'retained deep samples / deferred composition' may reduce work or add capability only while preserving its explicitly scoped output contract.

Contract: Same ordered deep samples produce exact declared ROI compositing, with retained-memory bounds and full-frame adverse workload.

Current opportunity/gap: Current surfaces represent flat images; no deep-sample parser, retained sample lists or ROI compositor exists. Historical CPU synthetic deep result does not supply OpenEXR I/O or GPU implementation.

Cheapest correct baseline: Strong decoded deep-state retention/checkpoint baseline composing only requested views, not gratuitously flattening full frame each time.

Primary outcome: Complete decode/process/present cost, transfers, command work or peak live storage for identical requested output.. No current metric was measured.

Bounded next test and falsifier: Define one bounded real deep input/sample-list adapter and independent ROI oracle; test sparse and full-frame views and reject changed depth/sample order. Charge initial parsing and storage.

Reopen when that named missing representation/owner/contract is provided or a changed workload exposes this exact opportunity. This is not a family-wide codec failure.
