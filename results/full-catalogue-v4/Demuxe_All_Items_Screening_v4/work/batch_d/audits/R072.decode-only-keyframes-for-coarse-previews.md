## R72 — Decode only keyframes for coarse previews

**Question.** When the requested output is a sparse keyframe storyboard, can non-keyframe reconstruction be skipped? This is different from R64's reduced-resolution reconstruction and R55's preview caching. The documented `skip_frame=nokey` control discards non-keyframes. It does not provide arbitrary exact-frame access. [F2]

The reference fully decodes a 12-second 1280×720 H.264 fixture, selects its I frames and scales them to 320×180. The candidate decodes keyframes only and uses the same scaler. The fixture has a closed 60-frame GOP, B frames and no scene-cut keyframes; the selected frames are 0, 60, 120, 180, 240 and 300.

All six resized-frame hashes and complete frame records match. Median CPU is **828.87 → 101.55 ms**; wall time is **464.74 → 96.39 ms**. The candidate does less temporal work without changing these selected images in this fixture.

**Admission contract:** explicitly coarse previews, never normal playback or exact scrubbing. Use a separate preview decoder, preserve source identity and geometry, and bound decode time and retained images. Expand the oracle to long/open GOPs, VFR, interlaced content, other codecs and cancellation before integrating. No browser preview UI or Emscripten decode was benchmarked here.

Evidence: [frame records and timings](results/r72_host.json), [script](scripts/r72.py).

## First-pass decision

Hypothesis: The proposed mechanism 'Decode only keyframes for coarse previews' may provide the specified output with less work or add a faithful route for its stated profile.

Contract: Explicit coarse keyframe storyboard retains selected image identity and geometry; never substitutes for exact scrubbing or playback.

Current gap: No maintained coarse-preview service or explicit skip_frame policy exists. Historical host hashes/CPU support a coarse-only experiment, not a browser result or permission to alter playback decoding.

Cheapest correct baseline: Same coarse keyframe storyboard from full decode and identical scaler.

Primary outcome: Time to the requested exact or explicitly approximate preview, total prerequisite work and retained state. No numerical outcome was measured.

Bounded next test and falsifier: Define one source-scoped coarse preview job and use existing decode harness only after that API exists; open-GOP/non-key request must not masquerade as exact seek.

Reopen only when the named missing contract/owner exists, a concrete workload exposes removable work, or the stated next slice changes this finding. A historical report assertion is not a newly verified current result.

Limits: per-mechanism source screen only; code/test presence does not prove successful runtime. No generic family verdict or missing-source inference was used.
