## R272 — ROI `VideoFrame.copyTo`

Chromium created a 640×360 `VideoFrame` from a deterministic RGBA canvas. The requested rectangle was x=112, y=73, 257×149.

`VideoFrame.copyTo()` with that rectangle returned 153,172 bytes, exactly matching the same rectangle cropped from a 921,600-byte full-frame copy: zero differing bytes and maximum error zero. That is an 83.38% reduction in application-visible transfer bytes.

Across the microprobe, median ROI copy time was ~0.1 ms versus 0.5 ms for the full copy. These are copy/transfer timings in this headless runtime only; they are not claims about full render cost, hardware residency, or all pixel formats.

## First-pass decision

Hypothesis: The proposed mechanism 'ROI VideoFrame.copyTo' may provide the specified output with less work or add a faithful route for its stated profile.

Contract: Only an explicitly requested ROI is copied, byte-equivalent to full-copy crop for admitted format/alignment; whole playback picture remains intact.

Current gap: Current retained presentation transfers complete VideoFrame resources; fallback copy reads the full visible rectangle because downstream playback needs the whole picture. There is no ROI analysis consumer to justify a cropped copy in this profile.

Cheapest correct baseline: Current no-copy retained presentation, or full visibleRect fallback for whole-frame consumers.

Primary outcome: Correct additional admitted source/destination capability; otherwise full startup and CPU/resource cost. No numerical outcome was measured.

Bounded next test and falsifier: Reopen for an actual ROI-only analysis request; then compare admitted rectangle copy against full-copy crop with subsampling-alignment negative control. Cropping playback output is not an optimization.

Reopen only when the named missing contract/owner exists, a concrete workload exposes removable work, or the stated next slice changes this finding. A historical report assertion is not a newly verified current result.

Limits: per-mechanism source screen only; code/test presence does not prove successful runtime. No generic family verdict or missing-source inference was used.
