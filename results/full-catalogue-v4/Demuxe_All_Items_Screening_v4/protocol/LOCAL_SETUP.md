1. Identify the authorized checkout, `git rev-parse HEAD`, local diff, package manager lock and actual served asset manifests. Historical commit `9abfd1b22300cf273fc0bd1a8290261281c8f3f3` is a reference from the reports, not asserted to be current.
2. Read the checkout's own instructions, package scripts, build/asset documentation and existing screening ledger. Do not assume a command named in an old report still exists. No fresh npm install, complete native build or full test matrix is a universal prerequisite.
3. Establish one unchanged working control for the selected runtime family. Reuse its result until a relevant artifact/input/assumption changes. Native/direct is the cheapest control when it satisfies the same requested operation; a Software-only baseline can exaggerate a candidate.
4. Touch the lossless-adaptation or subtitle baseline only for items depending on it. Verify matching JS/Wasm/glue/assets if used. Mixed artifacts are a setup error, not evidence about a codec.
5. Use current local event/trace output to distinguish candidate execution, fallback and intentional admission rejection. Do not infer hardware, physical output or process-wide CPU from a JavaScript option.
6. Scope fixture generation and malformed controls to owned synthetic media and bounded resources. No deliberate device exhaustion or repeated denied-folder scans. Paths supplied in the user's follow-up are local-agent evidence locations, not files guaranteed to exist in this ZIP.
7. Use source reviews and prerequisite gates while a separate family is blocked. A new origin server, preview service, cryptographic byte provider or decoder build family is not mandatory first-pass setup.
