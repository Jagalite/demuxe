# Native A/V plus mpv subtitles, current-tree comparison

[Raw trial records and fixture SHA-256 hashes](result.json) · [reproduction script](../../../tests/mpv-subtitle-tier-benchmark.mjs)

The comparison ran on Chrome 153/macOS with three alternating pairs per fixture. Each trial used a fresh browser. Forced Hybrid is the route the prior automatic policy selected; the candidate used automatic selection and selected `native-direct-mpv`. Both used the same local H.264/AAC fixture. The observed mpv subtitle service had zero A/V decode chains and a 64 MiB Wasm heap in each candidate trial. Startup, steady playback, forward/backward seeks, EOF, and player/worker teardown passed all 12 trials.

| Fixture | Route | Steady Chrome CPU, % of one core (three trials; median) | Startup median | Seek to 10 s / 1 s, median | Peak summed Chrome RSS, median | Renderer task time over 8 s, median |
| --- | --- | --- | ---: | --- | ---: | ---: |
| H.264 + AAC + embedded SRT / MKV | forced Hybrid | 57.9 (64.3, 57.9, 56.5) | 1,121 ms | 452 / 454 ms | 1,038,768 KiB | 0.19 s |
| same fixture | automatic Native Direct + mpv subtitles | 52.3 (52.3, 46.9, 52.7) | 1,286 ms | 40 / 44 ms | 1,144,864 KiB | 0.27 s |
| H.264 + AAC + styled ASS / MKV | forced Hybrid | 64.3 (64.3, 64.6, 63.0) | 1,110 ms | 449 / 268 ms | 1,123,712 KiB | 0.19 s |
| same fixture | automatic Native Direct + mpv subtitles | 52.0 (52.0, 51.0, 55.6) | 1,212 ms | 43 / 44 ms | 1,187,792 KiB | 0.27 s |

All six paired CPU differences favor the new route in this run. The candidate
had slower startup, higher sampled process-family RSS and more renderer task
time in the medians for both cases. These are workload-specific observations,
not a universal CPU or memory ranking.

The candidate had six observed workers (subtitle worker, four Emscripten pthreads, local I/O worker); Hybrid had eleven (retained engine, eight Emscripten pthreads, decoder, I/O). The measured peak process-family RSS is a sum of `ps` RSS values and can double count shared pages. Renderer `TaskDuration` excludes worker work. Chrome CDP CPU excludes OS media services and the fixture server. Browser decoder allocations are opaque. The host was shared, so CPU and memory are not isolated-host claims. The text/bitmap fidelity and track lifecycle checks live in `tests/mpv-subtitle-generalization.mjs`; this campaign checks whole-player progression, route, seek and EOF rather than redoing pixel comparison.

## Subtitle qualification

The [correctness run](correctness.log) exercised automatic Direct and forced Remux
for each of the five single-track combinations, plus two SubRip tracks. It
checked visible cue/bitmap changes around authored boundaries, forward/backward
seeks, re-enable, track disable/reselect, playback rate, zero mpv A/V chains,
and teardown. SubRip and mov_text exposed the exact marked text
`DE MUXE TEST 123` at 0.75, 6, 10 and 1 seconds, absent at 0.25 and 35.9.
ASS retained a magenta styled bitmap; PGS drew its bitmap from 0 through the
early clear event and restored it on backward seek; VobSub drew its palette
bitmap until 35.3 seconds and restored it after seeks. Each active rich/bitmap
sample contained more than 1,000 marked magenta pixels. The
Remux plan used the existing window-owned packet-copy MSE scheduler after an
intermittent teardown of Chrome's worker-owned MSE handle was observed in the
first test iteration; the final 12-case run had no remaining workers. The separate
`tests/mpv-subtitle-adverse.mjs` run passed no-subtitle Native regression,
enabling subtitles after an initially disabled Native open, unsupported/malformed
fallback, missing-font rejection, explicit old Hybrid opt-out, source replacement
with a pending render, stale worker retirement and destruction during
initialization. The 4 MiB local slice cache, 8,192-request limit and cancellation
contracts passed `node --test tests/file-reader.mjs`.

The last three fixtures are generated by
`python3 tests/mpv-subtitle-fixtures.py` from catalogue assets. The original
PGS/VobSub comparison rows have AC-3 audio and therefore remain Hybrid or
Software candidates; these derivatives isolate subtitle capability with
browser-compatible H.264/AAC A/V. This evidence does not qualify all ASS font,
karaoke/vector features, every tx3g style, or arbitrary bitmap object/palette
streams. Embedded WebVTT, mixed subtitle codecs, more than two SubRip tracks,
external rich subtitle files, and remote sources are not admitted.

The browser qualification used the service artifacts identified by SHA-256 in
`result.json`. `scripts/build-subtitles.py` links the pinned full subtitle
decoder archive and dav1d archive; the build products are ignored runtime
assets, so a fresh checkout must build them before running this route.
Non-release beta packaging now includes built subtitle assets by default and
its synthetic package test verifies the files and route manifest. A tagged
release still fails the explicit clean-source subtitle-engine qualification
gate. An attempted package of this shared working tree also hit an inherited
absolute build path in `web/engine-hybrid/player.wasm`; this run does not claim
a verified installable archive or release qualification.

Reproduce from a built tree with the pinned fixtures in `build/head-to-head/assets-component-isolation-01/fixtures`:

```sh
node tests/mpv-subtitle-tier-benchmark.mjs
```
